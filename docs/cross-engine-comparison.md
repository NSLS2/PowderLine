# Cross-engine comparison

The same two reference data sets, refined by every engine PowderLine drives
and by each profile model the engines offer, side by side. The point is to
show what to expect when you move a recipe between engines and *why* the
numbers differ — not to rank the engines.

The numbers below are generated by `scripts/cross_engine_comparison.py` on
the committed examples (the native `gsasii.rietveld` recipes of 0.2.0, with
the pinned engine versions); the "Versions and dates" footer says which run
produced them, and the GSAS-II rows are regenerated whenever the examples or
the pin change.

## How to read the tables

- **Cases.** `LaB6` (NIST SRM 660-series lanthanum hexaboride, one phase) and
  `DRX_33` (a cubic disordered rock-salt phase plus monoclinic Li4MgWO6, two
  phases). Both fit the window 1–15° 2θ of the same synchrotron pattern
  (λ = 0.1665 Å): 3767 weighted points for every engine (the fit limits sit on
  data points, so no engine scores a point another does not).
- **Rwp, Rexp, GoF** are PowderLine's *uniform* statistics: the same formula
  over the same points in every row, with the engine's own count of varied
  parameters. They compare how well each **model** fits those points. They do
  not say which engine is "right": a lower Rwp usually means a richer model
  (background peaks, more profile terms), not a better engine.
- **Δ vs GSAS-II** is the difference from the GSAS-II row in parts per
  million and in units of the combined standard uncertainty
  σ = √(ESD² + ESD_ref²). For LaB6 the second pair of columns compares with
  the NIST SRM 660c certificate value.
- **Source** says whether the row was produced by running the engine for this
  page (`run`) or read from a committed golden (`golden`). **TOPAS is never
  executed for this page**: PowderLine's maintainers do not have a TOPAS
  licence on the machine that builds the docs, so the TOPAS rows are the
  gateway's result rebuilt from the committed TOPAS 6 output files
  (`tests/data/topas/native/golden/6/`).

## What the differences mean

### LaB6: axial asymmetry moves the cell

LaB6 at 0.1665 Å has sharp, strongly asymmetric low-angle peaks (axial
divergence). How a profile model handles that asymmetry decides where it
puts the peak centroid, and therefore the lattice parameter:

- **Physical axial asymmetry (Finger–Cox–Jephcoat).** GSAS-II (SH/L) and
  easydiffraction's CrysFML Thompson–Cox–Hastings profile with FCJ asymmetry
  model the same physics. Their cells agree within about 10 ppm, i.e. within
  ~1.5 combined σ (engine-behaviour register EB-88).
- **Symmetric profile.** A plain pseudo-Voigt with no asymmetry term cannot
  follow the low-angle tails, and the fit compensates by shifting the peaks:
  the cell comes out **+67 to +91 ppm** larger, *whichever easydiffraction
  calculator runs it* (CrysPy pseudo-Voigt and CrysFML with the same plain
  pseudo-Voigt give the same shift). The CrysPy fit even reaches a slightly
  lower Rwp than the FCJ fit by driving the Lorentzian `X` term negative
  (register EB-87; the `easydiffraction_negative_width` warning) — a lower
  Rwp from an unphysical width, which is exactly why Rwp alone does not
  arbitrate.
- **Empirical asymmetry.** easydiffraction's Bérar–Baldinozzi correction, with
  its coefficients refined, fits the tails better still (Rwp 4.8 %) but
  correlates with the cell, which lands **+915 ppm** off (EB-88). It is not in
  the table because the committed fixtures do not use it; the register entry
  records the run.
- **GSAS-II-calculated data refined by easydiffraction (the temperature
  series).** On the six `example_LaB6_temperature_series` patterns,
  which GSAS-II calculated with a known cell and Uiso, CrysFML TCH + FCJ puts
  the cell **14–31 ppm low** (1.7–4 ESD) at every temperature while recovering
  the *expansion* to 0.8 %, and La's Uiso **10–22 % low** (8–12 ESD) with
  B's Uiso right; GoF is 1.01–1.04 in both engines (CrysPy's symmetric
  pseudo-Voigt: Uiso 17 % low, cell +68 ppm — the shift above). The probe
  (EB-93) points to **profile shape**: with CrysPy the engines'
  integrated intensities agree (no trend with angle once the integration
  window is wide) and its Uiso is still 17 % low, so the fitted offset is
  not an intensity difference; the trend is the same with Uiso = 0, and
  dispersion and the polarization mapping are ruled out. With CrysFML the
  trend shrinks with the window but was not shown to vanish (its TCH tails
  predict that), so a few-percent high-angle intensity difference is not
  excluded for CrysFML alone. The cause is the series' profile — GSAS-II's
  Lorentzian width, clamped to 0.001 centideg above ≈ 10.7° in the simulated
  peaks, the one part of it neither a symmetric pseudo-Voigt nor TCH with
  its FCJ terms held can represent; the mismatch lands in the parameter that
  dominates the angle dependence of the intensities (holding Uiso at the
  truth costs GoF 1.030 → 1.045). Shown by a test: the same pattern
  simulated with a GSAS-II profile easydiffraction can represent (the
  original `example_LaB6` posing) gives CrysPy La Uiso 0.00863 vs 0.00858
  programmed and GSAS-II 0.00868, while CrysFML lands at 0.00823 (−4 %, the
  size of its own intensity drift, EB-78). On this pattern the asymmetry
  moves the cell for the symmetric profile (CrysPy +76 ppm, an EB-88-size
  shift), not Uiso. Compare cells (with the EB-88-size offsets in mind) and
  expansion across engines; absolute Uiso agrees only when the profile
  models do.
- **TOPAS.** The TOPAS row is the cell-refined LaB6 fixture
  (`lab6_cell_rietveld`: the TOPAS LaB6 fixture with a, b, c refined), whose
  TOPAS 6 output files were produced on a TOPAS machine and reproduced there
  by `tests/test_topas_exec.py`. Its cell sits +87 ppm above GSAS-II's. The
  TOPAS fixture has no axial-asymmetry model, which is why its Rwp is the
  highest of the LaB6 rows; an unmodelled asymmetry shifts the fitted peak
  positions and so the cell, the same kind of offset as easydiffraction's
  symmetric pseudo-Voigt above.

**Against the NIST certificate.** All the refined LaB6 cells sit roughly
+80 to +180 ppm above SRM 660c's certified a = 4.156826(8) Å (k = 2, 22.5 °C).
That offset is common to every engine, so it is a property of the
measurement, not of the refinement: the recipe's wavelength and
sample-position terms (zero shift fixed at 0) were not refined against the
standard, and the recipe does not record the SRM lot or the temperature. The
NIST columns show the scale of that calibration offset; the Δ vs GSAS-II
columns are the ones that compare the engines.

**CrysFML start dependence.** CrysFML computes its pattern in single
precision and lmfit differentiates with steps smaller than that precision, so
a CrysFML *refinement* stops at a point that depends on its starting values
(register EB-90). Its refined cell is stable to about 1e-5
relative, but its Rwp and ESDs can move between runs. The row carries the
`easydiffraction_crysfml_start_dependent` warning for that reason; the
calculator remains available because PowderLine lets the user choose it and
states the difference.

### DRX_33: the profile models differ, and the data cannot tell them apart

The DRX_33 example is a two-phase refinement in which the GSAS-II recipe frees
per-phase isotropic size and microstrain (and their Lorentzian/Gaussian
mixing) with the instrument fixed, while the TOPAS fixture refines per-phase
Lorentzian and Gaussian strain terms (no size term), and the easydiffraction
fixture refines the instrument's U, V, W, X, Y instead of any per-phase
broadening. These are three different broadening parameterizations of broad,
overlapping peaks.

- TOPAS 6 and easydiffraction (CrysPy pseudo-Voigt) agree on the cubic cell
  within about 100 ppm (~1σ) and reach similar Rwp (7.2–7.3 %).
- GSAS-II's cubic cell is about 0.26 % (2600 ppm) smaller, with a nearly
  ten times larger ESD (so the gap is only ~3σ), and its Rwp is higher. The
  refactor's log attributes this to the engines' different profile models (the
  legacy 0.26.0 translation paths show the same gap): with peaks this broad,
  the cell, the strain terms and the background trade off against one another,
  and each engine settles that trade-off differently. The large GSAS-II ESD is
  the honest signal that the data do not pin the cubic cell down. GSAS-II also
  reports that the example's five cycles did not reach its convergence
  criterion (`gsasii_fit_not_converged`, with two soft singularities among the
  size/strain terms); the values are reported as they stand, as the example
  always has.
- The monoclinic Li4MgWO6 cell differs between GSAS-II and the other two
  engines by up to 0.2 % in the axes and 0.1° in β — again inside the
  correlations of a minor, broad-peaked phase.

The DRX_33 comparison is therefore a warning about the *case*, not about an
engine: when a cell differs across engines by more than a few σ, look first at
what else each model was free to vary.

### What is and is not comparable

| Comparable across the rows | Not directly comparable |
|---|---|
| Rwp / Rexp / GoF (same formula, same 3767 points) | Scale factors (each engine's own convention) |
| The unit-cell report: columns `parameter, value, esd`, rows `cell_a … cell_volume` and the ESD rule (`powderline.reports.unit_cell_rows`; before 0.2.0 topas and easydiffraction wrote `a … volume`) | Whether a volume ESD is propagated (gsasii and topas yes, easydiffraction no) |
| Cells and their ESDs (same units) | Profile parameters (different parameterizations and units; see the engine pages) |
| The number of parameters varied (each engine's own count) | What those parameters are |

## Reproducing the page

- `pixi run -e gsasii python scripts/cross_engine_comparison.py` runs
  GSAS-II on the committed examples and rebuilds the TOPAS and
  easydiffraction rows from the goldens; then
  `pixi run -e easydiffraction python scripts/cross_engine_comparison.py
  --no-run --rerun-easydiffraction` re-runs the easydiffraction fixtures
  (keeping the GSAS-II rows just recorded) and reports how close the rerun is
  to its golden (within the documented tolerances).
- `python scripts/cross_engine_comparison.py --no-run` rebuilds the tables
  from committed files only (goldens plus the JSON record of the last GSAS-II
  run); the docs build never needs an engine. The "easydiffraction goldens
  reproduced" table above is the last `--rerun-easydiffraction` result kept
  in that record.
- `tests/test_cross_engine_comparison.py` runs the `--no-run` path and checks
  that both cases and all three engines are present.
- The TOPAS rows change only when the goldens are regenerated on a TOPAS
  machine.
